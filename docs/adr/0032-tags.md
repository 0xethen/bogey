# 0032: Tags label people, can grant permissions, and drive judging rules

**Status:** accepted (2026-10-17). Extends [0005](0005-people-and-permissions.md).

## Context

Organizers need to tell kinds of people apart inside one role: adult and student judges, mentors,
volunteers who may check people in. Event roles are one per person and fixed by the schema, and plugin
roles come from plugins. Hackathon 6 needed every project judged by one adult and one student judge.

## Decision

- **A tag is a named label** (`tags`) made by an org for every event (`event_id` null, org admins) or by
  an event for itself (organizers, while the org's `tags.eventTags` allows it; on by default). Turning
  `eventTags` off sets an event's tags aside: they stop counting, they aren't deleted.
- **People hold tags** (`tag_holders`). An org tag goes on org members, an event tag on event members;
  leaving drops it through the foreign keys. `public.set_person_tags` replaces one person's tags in one
  scope and is audited.
- **A tag can grant permissions** on top of a role. `private.holds_permission` also asks
  `private.tags_grant`, and the UI's `EventAccess` adds the same grants. A tag only adds; the holder
  still needs a role in the event.
- **Judging rules are settings.** `judging.assignment` holds judges per project, rules (`tag`, `count`,
  optional `division`, `strict`) and tags kept out. `assign_round_robin` tops every entry up instead of
  adding a fresh batch each run. Rules go first, least-loaded judge first; a rule that isn't strict stops
  at an even share of the work (one judge may go one over) and lets anyone fill the slot, a strict one
  doubles judges up and fails, assigning nothing, when no one with the tag is free of conflicts.

## Consequences

- Assigning twice no longer piles on judges; to give projects more, raise judges per project.
- Staff and organizers who hold a tag granting `judging.score` are in the judging pool.
